Prometheus × Langfuse 速查表

一个看全局趋势和告警，一个看单次 LLM 调用与质量原因。用 exemplar / trace ID 将二者连接。

选择工具

问题工具
吞吐、错误率、P95、CPU、连接池、队列Prometheus
具体请求、Prompt、输入输出、Token、成本Langfuse
Prompt 版本比较、Score、Dataset、ExperimentLangfuse
告警与 SLOPrometheus + Alertmanager
从延迟尖峰跳到具体请求Prometheus exemplar → Langfuse Trace

文档审核最小指标集

# Counter
document_review_requests_total{department,result}
llm_requests_total{provider,model,result}
llm_tokens_total{provider,model,direction}

# Gauge
document_review_queue_depth{department}
document_review_active_jobs{department}
database_pool_connections{state}

# Histogram
document_review_duration_seconds{department}
llm_request_duration_seconds{provider,model}

Label 边界

通常可以

department、environment、route、result、provider、受控 model。

禁止或谨慎

trace_id、request_id、document_id、session_id、用户身份、错误全文、Prompt、文档正文和输出。

每个 label 值组合都是新时间序列。精确 ID 放 Langfuse metadata；关联时用 exemplar，不要用普通 label。

常用 PromQL

# 各部门 QPS
sum by (department) (
  rate(document_review_requests_total[5m])
)

# 各部门错误率
sum by (department) (
  rate(document_review_requests_total{result="error"}[5m])
)
/
sum by (department) (
  rate(document_review_requests_total[5m])
)

# 各部门 P95
histogram_quantile(
  0.95,
  sum by (department, le) (
    rate(document_review_duration_seconds_bucket[5m])
  )
)
