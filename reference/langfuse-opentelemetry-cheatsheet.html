Langfuse × OpenTelemetry 速查表

判断“谁产生 Span、谁传播上下文、谁分发、谁存储、谁提供 LLM 评测能力”。

一句话分工

层一句话代表对象
Instrumentation把运行事件变成遥测信号CallbackHandler、FastAPI instrumentation
Context保持 Trace 父子关系Trace ID、Span ID、W3C traceparent
SDK采样、处理、排队和导出TracerProvider、SpanProcessor、Exporter
Protocol标准化传输遥测数据OTLP/HTTP、OTLP/gRPC
Collector集中接收、处理和多目标分发Receiver、Processor、Exporter
Backend存储、查询、展示和分析Langfuse、Tempo、Jaeger、Datadog

三种共存模式

选择使用条件注意
共享 TracerProvider同一进程、需要一致父子树集中控制初始化、过滤和脱敏
Collector 扇出多服务、需要统一重试和路由Langfuse exporter 必须用 OTLP/HTTP
隔离 ProviderLLM Trace 与 APM 数据强隔离跨 Provider 可能出现 orphan span

Langfuse OTLP 当前边界

  • 接收 Trace：/api/public/otel 或 /api/public/otel/v1/traces
  • 支持：OTLP/HTTP JSON、OTLP/HTTP protobuf
  • 暂不支持：直接向 Langfuse endpoint 使用 OTLP/gRPC
  • 认证：Authorization: Basic ${AUTH_STRING}
  • v4 实时处理：x-langfuse-ingestion-version: 4
  • Project 由 Public/Secret Key 对决定

可移植性边界

OTel 可移植

Trace/Span ID、父子关系、时间、错误、attributes、resource、instrumentation scope。

有条件可移植

模型、Token、Prompt/Completion 内容；依赖 GenAI semantic conventions 和平台映射。

Langfuse 专属

Prompt 管理、Score、Dataset、Experiment、Annotation Queue、原生成本和评测工作流。

生产检查清单

  • 由谁唯一初始化全局 TracerProvider？
  • 哪些 instrumentation scopes 允许进入 Langfuse？
  • 过滤后 root 与必要父 Span 是否仍保留？
  • Langfuse 与另一个 exporter 是否分别完成脱敏？
  • 是否误把文档原文、Secret Key 放进 attributes 或 baggage？
  • 多部门 Project 是否由认证后的部门上下文路由？
  • Collector exporter 是否为每个 Langfuse Project 使用正确认证？
  • 短生命周期任务是否 flush/shutdown？
  • 采样是否让 Langfuse 与 APM 得到不一致的 Trace？
  • 是否监控 Collector 的拒绝、队列和发送失败指标？
